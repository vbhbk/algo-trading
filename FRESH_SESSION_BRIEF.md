# Qminers Algo Trade Arena — краткое описание проекта (для новой сессии)

Правила соревнования, механика биржи и ограничения на файл стратегии — в приложенной презентации и разделе Info.
Ниже только то, чего там нет: данные, разбивки, как обучаем и проверяем, что уже известно и какая планка.

## 1. Цель и оценка
Один файл стратегии (`BaseStrategy`) торгует одним инструментом против фиксированного тейпа. Счёт = PnL на
**скрытых** данных раунда. С раунда 2 сайт считает каждую загрузку на отдельном **валидационном** отрезке
(~12 000 с, не совпадает с публичным файлом), а итог раунда — на **приватном**. Публичный файл — только для
разработки; главный риск — подгонка под него. Сейчас идёт раунд 3, впереди раунд 4 (вес 1,2).

## 2. Репозиторий и запуск
GitHub `vladyslavzk/algo-trading` (шаблон организаторов `QminersOrg/qminers-algo-arena`). `simulator/`, `explorer/` —
код организаторов, **не менять**. Окружение: `uv sync`. Бэктест:
```bash
uv run exchange-simulator --strategy strategies/X.py --backtest data/Y.csv --log-dir logs/Z --no-logs
```
`logs/Z/result.json`: `pnl, pnl_se, breach_penalty, fills, abs_inventory_q50..q997`; `pnl.csv` — PnL по секундам.
Перебор параметров (константы уровня модуля): `research-tools/sweep.py` (см. docstring).

## 3. Данные (`data/`, в git не хранятся — загружаются отдельно)
| Файл | Что это | Длительность | Характер рынка |
|---|---|---|---|
| `sample.csv` | синтетика организаторов | 1 ч | искусственный тренд — **не использовать для настройки** |
| `sample_v2.csv` | публичный файл тренировочного раунда | 5 750 с | спокойный, спред ~1 |
| `round1.csv` | публичный R1 | 12 000 с | спокойный: диапазон ~100 тиков, ни одного скачка ≥5 тиков за 1 с |
| `round2_public.csv` | публичный R2 | 6 000 с | волатильный: обвал −361 тик за 10 мин, отскок +200; 409 скачков ≥5 тиков/с |
| `round3_public.csv` | публичный R3 (текущий) | 6 000 с | волатильный в обе стороны (−229, +206, −170 за 10 мин), 670 скачков ≥5 тиков/с |

Цены — целые тики около 10 000, объёмы — лоты. Во всех файлах: лимитные заявки медиана 14–18 лотов, IOC ~2,3%
строк (медиана 60, среднее ~160 лотов), ~47% строк — отмены. Спред: R1 ~1, R2/R3 в среднем 1,25 (p90 = 2).

## 4. Разбивки (как обучаем и проверяем)
Правило команды: **подбор только на train, validation — одна проверка выбранного варианта**, ничего по ней не
выбирать. Отдельного test нет; финальная проверка — загрузка на сайт (1–2 на кандидата, их ~10 за раунд).
| Разбивка | train | validation | Примечание |
|---|---|---|---|
| Половины по времени (основная) | `<round>_a.csv` (первая половина) | `<round>_b.csv` (вторая, время сдвинуто к 0, отмены заявок из первой половины выброшены) | есть для round1, sample_v2, round2, round3 |
| Для ML-моделей | первые 60% `_a` (обучение весов) | последние 40% `_a` (`round3_a2.csv`, подбор порогов) | затем одна проверка на `_b` |
| Разбивка напарника (R2) | `round2_public_train.csv` (0–4 020 с) | `round2_public_valid.csv` (4 020–6 000 с) | `round2_t40.csv` = последние 40% его train |
Скрипт нарезки половин: взять `Time < T/2` → `_a`; остальное → `_b` с вычитанием первого времени и выбросом
`Cancel` для id, вставленных в первой половине.
Для загрузки модели после проверки переобучаются на **всём** публичном файле раунда.

## 5. Варианты обучения, которые уже есть
1. **Правила с параметрами** (маркет-мейкер: размер котировок, лимит позиции, фильтры) — перебор `sweep.py`.
2. **Обучаемая модель направления** (ветка `max/vol-guard`): `logs/max/r3/record.py` прогоняет тейп стратегией без
   заявок и сохраняет 33 признака `DirectionModel` (из `strategies/strategy_v8.py`) на каждом событии;
   `logs/max/r3/fit.py` строит цель = сдвиг mid через H (0,25 с и 2 с), стандартизованная ridge, λ выбирается на
   последних 30% train; веса подставляются в стратегию. Признаки: OFI и знаковый агрессивный поток на 0,1–10 с,
   mid − EMA (0,5–60 с), sweeps, объём, реализованная волатильность, дисбаланс L1 и глубины 5 тиков, microprice,
   скорость изменения объёма у лучших цен, время с последней смены цены, последний агрессор. Модель активна только при спреде 1.
   Найдено: R² на R3 holdout 0,23 (0,25 с) и 0,08–0,10 (2 с); +8 признаков (скорость mid, размах, крупные агрессоры,
   разрыв до L2) улучшили R² на 3%, но не PnL.

## 7. Что известно (проверено измерениями)
- R1 — спокойный рынок: деньги в пассивных заявках и месте в очереди; крупный размер у лучшей цены и разгрузка позиции на всю ёмкость.
- R2/R3 — **информированный поток**: после агрессивной сделки цена уходит в её сторону и не возвращается; чистый
  маркет-мейкинг убыточен; работает только с моделью направления. Модели, обученные на R2, переносятся на R3, а переобучение на свежих данных даёт +23%.
- Слепое снятие котировок (по потоку, после крупных сделок, по дисбалансу) проигрывает — теряется очередь; снятие **по прогнозу модели** выигрывает.
- Не сработало: следование за потоком IOC без модели, улучшение цены внутри спреда 2 тика, ловля скачков глубокими заявками или IOC по скачку, сдвиг цен от позиции (skew) в R1.
- Лимит: любая механика должна гарантировать |позиция + свои заявки на стороне + IOC в полёте| ≤ лимит (мы держим 95; штраф с 100, $10 000/с). Одна IOC-механика однажды дала позицию 213 и штраф в миллионы.
- Песочница: 15 мин на прогон валидации (~12 000 с); наши ML-стратегии идут ~2,5 мин на 6 000 с локально — укладываться в ~5 мин на 12 000 с. Запрещённые имена ловятся статически (не называть переменные `io`, `type`, `open`).
- Коммиты без `Co-Authored-By` и упоминаний Claude, короткие комментарии в коде.
